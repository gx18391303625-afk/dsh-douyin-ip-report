# 抖音侵权举报

仅处理用户本次明确提供的目标。通过专用浏览器后台运行，不使用系统鼠标、键盘或剪贴板，不自动回退有头模式。只有用户明确发起登录时才打开扫码窗口。

## 类型与必要输入

- `patent`（专利）、`trademark`（商标）：走 https://www.douyin.com/qinquan/report?enter_from=pc_douyin ，选择「假冒专利」或「假冒商标」。需要对应本机话术、证明材料与组织身份，见 [materials.md](references/materials.md)。
- `original`（用户说「原创」）：走目标视频的「举报」→「搬运、抄袭作品」，在独立字段填**对应原创作品 URL**；不走 qinquan 专利/商标表单，不需要专利图片、组织身份或材料目录。
- 目标 URL 与原创 URL 是不同角色。必须有用户明确提供的原创链接，或当前已知且经用户确认的目标→原创关联；缺失或不明确先问，不能用旧演示原创链接套新目标。一个共享原创只能用于用户明确指定的本批目标范围；多组用逐目标映射。
- 类型不明才询问；用户已写「原创」就映射为内部 `original`，不再问专利还是商标。不自动将同一目标按多种类型提交。

## 本机环境与首次检查

需要 Python 3.10+、Node.js 20+、Google Chrome 和 `playwright-core`。私有配置、任务与 profile 不随插件分发；见 [local-host.md](references/local-host.md)。首次使用、用户说「开始检查」或环境不明时，运行 `scripts/host.py --host deepseek setup`（macOS/Linux 用 `python3`，Windows 用 `py -3`）。缺系统软件先征得同意；`setup --fix` 只安装 `playwright-core`。

专利/商标缺身份或材料时向用户索取，已有目录可用 `setup --set-materials <目录>`；`init` 只补缺、不覆盖。原创用 `setup/doctor/check --kind original` 只检查运行环境、对应原创链接与其独立登录态，不能因缺专利/商标材料而阻塞。登录失效时先请用户进行登录，再运行 `login --kind original`（原创）或普通 `login`（专利/商标）；扫码窗口不代表已登录。正常执行无头运行，不复制日常 Chrome 登录数据库；原创使用独立 `original-browser-profile`。

安装、更新、setup、登录和自测均不是提交授权。没有本次用户目标只可检查配置、按用户请求登录或查询历史；不重放演示、不默认读旧工作簿。小样本也只能使用用户指定的目标，检查阶段不传 `--submit`。

## 输入、授权与确认开关

1. 从本次分享口令/文案提取 `v.douyin.com` 与 `/video/<id>` 链接，解析短链、去重并报告目标数量；保留短链尾部斜杠。原创链接须与目标分开记录，不能混入目标清单。
2. 用户明确粘贴目标链接并指定类型，即按现有确认开关执行本批 prepare/run 请求；单纯询问、检查、准备或调试不提交。明确的「只准备」始终优先。
3. 最终提交前运行 `host.py settings`：`confirm_before_submit: true` 时汇总类型、条数及依据并等明确确认；`false` 时可按本批明确请求直接提交，但仍先 prepare 核对范围。读取失败按 true。只有用户能在侧边栏改开关，agent 不得改文件或绕过。
4. 专利/商标摘要含组织与附件数；原创摘要含目标→原创关联，不索要无关证照。开关关闭不授权未知目标、未知原创关联或重放旧任务。

## 执行与结果

详细命令见 [execution.md](references/execution.md)。

1. 专利/商标先 `check`，核验材料与组织；原创用 `prepare --kind original --links-file ... --original-link URL` 或 `--originals-file JSON`，不借用专利材料。`prepare` 永不提交。
2. `run --job <任务>` 复用任务类型与稳定状态文件，默认只填表/检查；只有符合本批授权及确认设置才加 `--submit`。不删除状态、换路径或改类型绕过去重。
3. 验证目标、识别数量、字段及页面类型。专利/商标还核验上传完成和组织；原创核验当前视频与独立原创 URL。页面变化、登录/验证码/风控或定位失败就停，不猜测继续，不自动改为有头或系统输入。
4. 过滤、重复、不可见、未识别均不算成功。部分接收不重投整批；`--retry-failed --submit` 仅用于执行器明确失败且仍获授权的同一任务。`submitted_unknown`、其他 uncertain/结果不明状态不能自动重试。
5. 专利/商标用只读 `status` 查询 qinquan 历史/回执，按视频 ID 核对。原创单独报告本地任务状态与直接页面证据；qinquan 历史不能确认原创举报，不能编造批次号、回执或审核结果。表单清空不证明成功，平台接收不等于审核通过。

「24 小时内已举报过」只证明本次被拒，不能推断原举报仍在审核或已通过。查不到或查询不完整就明确说未确认；不同电脑/宿主的本机去重记录不共享。

## 验证边界

专利/商标既有实测范围见 [workflow.md](references/workflow.md)，不能将它当作原创流程已实测或已获平台受理的证据。本地自测只证明合成页面行为。页面变更导致定位、上传、原创关联或身份核验失败时停止并报告具体位置。
